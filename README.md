# tg-business-kit

One Telegram bot engine for small service businesses — language schools, dental clinics, beauty studios, tutors. Every client is one JSON profile: services, weekly slots, FAQ and UI texts. The engine turns it into a button-driven booking flow, an FAQ menu and AI answers grounded strictly in the profile; whatever the profile does not answer goes to the owner.

Status: phase 2 of 4 — long polling and a webhook server, Docker image, CI. Leads still live in memory; Postgres comes next.

## Try it

```bash
uv sync
uv run python -m kit validate presets/*.json
uv run pytest
```

Run a bot against your own test token (create one with @BotFather):

```bash
uv run python scripts/setup_env.py          # hidden prompts, writes .env (600)
uv run python -m kit run --profile presets/dental-clinic.json
```

## Docker

```bash
docker compose up -d --build                     # long polling, no public URL needed
docker compose --profile webhook up -d --build   # webhook server on 127.0.0.1:8000
```

`KIT_PROFILE=presets/language-school.json` picks another business. The webhook port is bound to localhost on purpose: put a TLS reverse proxy in front of it, then `uv run python scripts/set_webhook.py https://<host>/telegram/webhook`.

Check a running webhook server without Telegram:

```bash
uv run python scripts/synthetic_update.py http://localhost:8000/telegram/webhook "hi"
uv run python scripts/synthetic_update.py http://localhost:8000/telegram/webhook --no-secret   # 403
uv run python scripts/webhook_info.py
```

## Environment

| key | needed for |
|---|---|
| `TELEGRAM_BOT_TOKEN` | always |
| `GEMINI_API_KEY` | `modules.ai_answers` |
| `ADMIN_USER_ID` | owner notifications and `/leads` |
| `WEBHOOK_SECRET` | `serve` — generated by `scripts/setup_env.py` |
